# astrbot_plugin_nova_gpt_image

支持基于 GPT-5.4-all 及其它兼容 OpenAI 流式图片输出格式的大模型生图专属插件。

✨ **由全能战略官人格 Agent Nova 专属定制开发** ✨

仓库地址：[https://github.com/YumenoSayuri/astrbot_plugin_nova_gpt_image](https://github.com/YumenoSayuri/astrbot_plugin_nova_gpt_image)

## 特性

- **支持流式（Streaming）与非流式**：兼容 `chat/completions` 与 `images/*` 系列端点。
- **支持多模态图生图**：附带图片或引用带图消息时，自动按图生图路线处理。
- **四路独立配置**：支持分别配置：
  - 普通用户-文生图
  - 普通用户-图生图
  - 白名单用户-文生图
  - 白名单用户-图生图
- **白名单高清策略**：白名单用户可额外启用 `4K/2K/1K + 比例` 智能尺寸映射。
- **URL/Base64 双格式兼容**：支持 `url`、`b64_json`、Markdown 图片链接、Base64 内嵌图片。
- **完备下载机制**：支持图片下载超时和重试。
- **旧配置兼容**：若未填写四路专用地址/模型，会自动回退到旧版单路 `provider/api_url/model` 配置。

## 适用指令

- `/GPT生图 描述内容`
- `/GPT 描述内容`

插件会自动保留第一个空格后的完整内容，不会吞掉后续 prompt。

## 路由逻辑

插件会先判断两件事：

1. 当前用户是否在 **白名单 QQ**
2. 当前消息是否包含 **图片 / 引用图片**

然后自动选择以下四条路之一：

| 用户类型 | 是否带图 | 使用配置 |
|---|---:|---|
| 普通用户 | 否 | 普通用户-文生图 |
| 普通用户 | 是 | 普通用户-图生图 |
| 白名单用户 | 否 | 白名单用户-文生图 |
| 白名单用户 | 是 | 白名单用户-图生图 |

如果对应路线未填写 URL 或模型，则会自动回退到旧版默认配置。

## 配置说明

在插件配置面板 `astrbot_plugin_nova_gpt_image` 中：

### 一、旧版兜底配置
- **API提供商 (旧兼容/默认兜底)**
- **旧手动配置: API URL（兜底）**
- **统一 API Key**
- **旧手动配置: 模型名称（兜底）**

这几项用于兼容旧版本，或者作为四路专用配置未填写时的回退方案。

### 二、四路专用配置

#### 普通用户
- **普通用户-文生图 API URL**
- **普通用户-文生图 模型**
- **普通用户-图生图 API URL**
- **普通用户-图生图 模型**

#### 白名单用户
- **白名单用户-文生图 API URL**
- **白名单用户-文生图 模型**
- **白名单用户-图生图 API URL**
- **白名单用户-图生图 模型**

### 三、白名单配置
- **白名单 QQ（逗号分隔）**

例如：
`123456,789012`

白名单用户不仅可以走单独的地址和模型，还能启用智能高清尺寸解析。

### 四、其它配置
- **图片下载超时时间（秒）**
- **图片下载重试次数**
- **API请求等待超时时间（秒）**

## 智能尺寸识别

仅对白名单用户生效。

只有当 prompt 中 **同时出现质量关键词和比例关键词** 时，插件才会自动传入具体 `size`。

### 质量关键词
- `4K` / `4k`
- `2K` / `2k`
- `1K` / `1k`
- `1080`

### 比例关键词
支持以下写法：
- `1:1` / `1：1` / `1-1` / `1比1`
- `16:9` / `16：9` / `16-9` / `16比9`
- `9:16`
- `4:3`
- `3:4`
- `3:2`
- `2:3`

### 尺寸映射示例

| 质量 | 比例 | 分辨率 |
|---|---|---|
| 4K | 16:9 | 3840x2160 |
| 4K | 9:16 | 2160x3840 |
| 4K | 1:1 | 2880x2880 |
| 4K | 3:2 | 2880x1920 |
| 2K | 16:9 | 2560x1440 |
| 2K | 1:1 | 2048x2048 |
| 2K | 3:2 | 2048x1365 |
| 1K | 16:9 | 1920x1080 |
| 1K | 1:1 | 1024x1024 |

### 注意
- 只有 **质量 + 比例** 同时存在才会传具体 size
- 只写 `4K` 或只写 `16:9` 时，插件不会强塞尺寸，仍交给上游默认处理

## Images 端点说明

当路线配置为 `images/generations`、`images/edits` 或其它 `images/*` 端点时：

- 插件会走非流式 JSON 处理
- 默认自动附加：
  - `output_format: png`
  - `quality: high`
- 如果消息中有图片或引用图，会自动把图片注入 payload 中

注意：当前插件会根据您配置的 URL 路线走，不会擅自替您改端点；也就是说，**图生图是否走 edits 还是 generations，取决于您在“图生图 API URL”里填什么。**

## 技术细节

- **超大图片支持**：`aiohttp` 读取缓冲区已提升到 100MB
- **流式图片识别**：支持从 SSE 流中提取 Markdown 图片链接
- **多格式下载**：支持 URL 下载、Base64 解码、b64_json 解码
- **引用图识别**：支持从 `Reply` 链中提取图片并自动进入图生图路线
- **完整日志**：记录路由选择、尺寸识别、图片下载等关键步骤

## 推荐配置思路

### 方案 1：普通用户便宜模型，白名单用户高质量模型
- 普通用户-文生图：低成本 chat/completions
- 普通用户-图生图：低成本 images/generations
- 白名单用户-文生图：高质量 images/generations
- 白名单用户-图生图：高质量 images/edits

### 方案 2：全部走同一个上游，只区分文图路线
- 普通用户和白名单用户使用同一套模型
- 仅把文生图和图生图拆成两个端点

### 方案 3：只填旧版兜底配置
- 不填写四路专用配置
- 全部回退到旧版单路逻辑
- 适合最简部署
